# Re-shoot sweep, 2026-08-24 — what the next arm should not have to rediscover

Arm B. 24 clips re-shot from ghosts regenerated on the current pipeline, each
one `ghost verify`-clean end to end and each one watched on frames before it
shipped. This file is the part that is not in the clips.

---

## 1. Our sample bytes are what the game client rejects — not the record

Three maps produce a regenerated ghost the client refuses or dies on, while the
container's own untouched record imports every time: **279209**, **228811**,
**227654**. Every headless gate passes on the refused files — V1–V11, kappa
1.000, the plain oracle exact — so nothing we run offline can see this.

`ghost record resample IN OUT --from SRC` was written to split the two
candidates. It takes the file that imports and overwrites **only the car's
sample bytes**, instant for instant. On 279209:

* resampled file → **the client still dies**.
* control: `resample X OUT --from X` → **byte-identical to X**
  (md5 `4721d922c2e31b6b275b315ef030170a` both sides). The round-trip is a
  provable no-op, so the 132 × 116 bytes of car state are the only difference
  between the file that imports and the file that kills the game.

**So the search is now "which byte value does the client reject", not "what is
wrong with our record".** `tmtraj bytes` can drive it.

What did NOT work, both worth not repeating:

* `graft-scene --from <a downloaded human recording of that map>` — on 228811 it
  still dies; on 279209 it changes the failure (the game stops dying and starts
  refusing the import, block count 0 → 0 with a `FrameMessage`). Different
  failure, not a fix.
* `resample` on 228811 at all — it refuses, correctly. That map's published file
  samples at 20, 70, 120 ms and the regeneration at 0, 50, 100. No shared
  instant, and a 20 ms shift there is 1.78 m of error.

**Not yet done, and it is one command:** `resample` on 227654. Its importing
container is ailiei.'s raw 147.031 download (29 entities, several of them cars)
and our run is 57.482, so the instants do not line up end to end — it needs the
container trimmed first, and trimming rebuilds the record, which is the thing
under test. Worth doing carefully rather than quickly.

## 2. `ghost regen` reorders the record's entities, and that alone can make a file unimportable

On **203072** the container has the car LAST of three; the regeneration puts it
first; the import then fails four times with the block count 0 → 0 and a
`FrameMessage`. The map's own published ghost imports first try in the same
scene seconds later. `ghost record entorder --car-last` fixes it and the render
runs.

The rule is **not** "the car is entity 0" — `entorder`'s own help says that, and
203072 is a counter-example that imports fine. The rule is *the order its
container had*. `ghost regen`'s finishing pass now restores it automatically and
says so; 203072 is the only map in the corpus where the two disagree.

## 3. Welcome to wiggles: byte 59 dead, and `--quat-kind` hides it without fixing it

197047 refuses four times out of four: **byte 59, the orientation angle, comes
out `0x00` on all 1917 samples**, where the published file has it live from the
second sample (`253, 233, 189, 124, 64 …`).

* **It is the map, not the pipeline.** Control: on Torment (1-UP) the
  regeneration reproduces the published orientation block, bytes 59–62,
  **byte for byte on every sample**.
* **The lead is in the locate.** 197047's accepted anchor reports
  `pos +196, quat +252` — the quaternion **56 bytes after** the position. Every
  map that works puts it before: `+180` (228811, 165922, 252289, 279209, 270051,
  126859), `+192` (267859), `+160` (191465, 285268), `+44` (173636).
* **`--quat-kind` 1 and 2 both pass with zero refusals** and a trajectory
  0.0000 m from the published file — and their orientation reproduces nothing.
  At 0.050 the published file reads `253 127 255 255`; kind 1 reads
  `0 128 0 0`, kind 2 reads `25 85 0 0`. Neither was shipped. A flag that turns
  a refusal into a pass is not a fix unless the thing the refusal was about got
  better.
* **Tap water 01 hit the same refusal and recovered on a retry** — byte 59 live
  the second time and matching its published file. So the failure is
  nondeterministic per attempt on most maps and deterministic on 197047, which
  is itself the evidence that 197047 is different.

## 4. Two `ghost regen` gates were refusing correct work

Both fixed with controls; between them they blocked twelve maps.

* **Channel liveness scanned the whole tape** while the record samples only the
  race. Any run flat out from the lights to the line has accel 0 in the
  countdown and 1 for the whole race, so the scan said "this input varied" and
  the constant gas echo read as a dead channel. Now windowed to the record's own
  span. Control on the same file: `ghost tape stats --from 0 --to 6578` reports
  accel CONSTANT at 1 for all 658 in-race ticks while the whole tape reads 0..1,
  and brake and steer still vary in that window, so the check keeps its teeth.
* **Donor-byte provenance treated "bit-identical to the donor" as
  contamination**, which is right when the donor is a stranger's container and
  wrong when it is the map's own previous generation of the same tape. It
  refused five correct files on three to seven low-entropy bytes each — turbo,
  gear, ground contact, ground material — every one a byte `--carrier layout`
  had just written from engine memory. Now split: a byte we do not write is
  still refused outright; a byte we do write is reported with its ratio, and the
  whole-set case (the gather not running at all, c01a842) is its own refusal at
  90 %.

## 5. Comparing two runs at matched samples cannot see a sampling-phase difference

228811 read a **mean 1.78 m "trajectory shift"** that is entirely the two files
being sampled 20 ms apart at 320 km/h. Sample-to-sample comparison has a floor
of half a sample-step; point-to-polyline has none.

`tmtraj geom near --segments` is the form to use. Controls: a file against
itself 0.0000 m, against a different run 52.3 m, and 228811 against its own
regeneration **0.0078 m**. Every "the trajectory did not move" number in this
sweep is measured that way.

**Related, from the Training - 10 Long arm and not yet chased:** `ghost regen`
labels that map's *search* tapes one whole tick late while labelling a
downloaded human recording of the same map correctly — deterministic, 5 runs
each way, and `ghost regen-control` passes it. **It inverts any comparison
between two regenerated records at matched sample indices.** Point-to-polyline
is largely immune; anything index-matched is exposed.

## 6. The Magnet Trial is shot on `--cam 1`, the cockpit — reuse it

Magnet map: the car spends most of 793.893 s on walls and ceilings and the stock
chase camera keeps the WORLD's up-vector. Picked by looking, three partial
renders, same instants, via `clip frames --stream`:

| | race 4.000 | race 8.000 |
|---|---|---|
| `--cam 2` External | small and far; a car glued sideways to a pillar | **no car in frame** |
| `--cam 6` Ext2 | the best single image on this map | **no car in frame** |
| **`--cam 1` Internal** | nose and wheels, road ahead, world rolled with the car | **car and road in frame** |

Cam 6 takes the prettiest frame and is the wrong choice: at race 8 **both**
external cameras lose the subject, which is the map rather than the mode. The
cockpit never does. The trade is the car's own body, and on a magnet map the
information is the attitude and the line.

## 7. Render-length: one real finding and one retraction

* **Real:** Leto rendered **441.000 s** with both staged ghosts ending by
  219.000. A render can be twice as long as anything in the scene; `clip cut`
  fixes it afterwards, at the cost of rendering the discarded part.
* **Retracted:** I wrote that the length is the map's author ghost, on the
  strength of The Magnet Trial's dialog estimating 01:45:52 for a 30 s slice
  (2540.641 s at 2.5× realtime = 6352 s = 01:45:52, exact). Rendered in full it
  produced **793.866 s** in about forty minutes. **The dialog's `estimated` is
  not a measurement of clip length**, no slice render was ever allowed to
  finish, and an arithmetic coincidence that lands on the second is more
  persuasive than a rough one and no more evidential.
* **`/clipend` does not work on this build.** `shootctl get /clipend?ms=N`
  answers `could not resolve CGameCtnMediaBlock::End`; the route and its
  implementation are both in HEAD and the member lookup is what fails.

## 8. Environment, and what each of these cost

* **The whitestick bridge cuts a command off at about two minutes.** Every long
  command must be detached on the box (`nohup sh script > /tmp/log 2>&1 &`) and
  the log polled. Run inline, a render looks like it died — and it orphaned a
  `lock acquire` that then had to be `kill`ed. Three attempts.
* **`shootctl lock acquire` is not re-entrant.** Acquiring while you already
  hold it blocks silently forever. Release first.
* **`shootctl setup` does not launch the game.** When one map's import kills it,
  every following map fails with `could not get back to the menu; ctx=None`.
  Four maps lost before `launch --force` went into the loop; it costs 15 s and
  makes one map's crash cost one map.
* **A plugin that does not compile takes the box down for every arm.** Openplanet
  unloads the plugin and the HTTP server goes with it; `launch` then reports
  "finished starting but the plugin is not listening". `shootctl lint` before
  installing.
* **`git clone` into `~/persistent` on an fbsource OD fails every time**
  ("premature end of pack file"). Clone into `/tmp`; it takes seconds.
* **`clip ship` now refuses over 100 MB before uploading anything.** GitHub's
  attachment store caps there, and the failure used to arrive as a 422 *after*
  the full-size original had gone to the release. Long clips need `--crf`: 218 s
  wants 24, 794 s wants 32.
* **Patches do not apply to a repo three arms are writing.** Half my commits
  landed the binaries and dropped the page edits because `git apply` failed
  atomically and the commit went ahead anyway. Copy whole files and `sed` the
  front page, then **re-read the file after the commit** rather than before.
  `README.md` in particular was reverted twice by whole-file edits from other
  arms — four dead embeds on the front page, silently.
