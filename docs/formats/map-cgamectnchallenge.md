# CGameCtnChallenge — the map (`.Map.Gbx`, class `0x03043000`)

The map is one `CGameCtnChallenge` node: a header (§1) the menu and the editor
read, and a body (§2) of ~50 chunks the engine reads. This page is the catalogue
and the header; each big body chunk has its own page:

| chunk | what | page |
|---|---|---|
| `0x0304301F` blocks, `0x03043048` baked blocks, `0x0304305F` free positions | `map-blocks.md` |
| `0x03043040` items + `0x03043062`/`0x03043068`/`0x03043063`/`0x03043069` side tables | `map-items.md` |
| `0x03043043` zone genealogy | `map-genealogy.md` |
| `0x03043054` embedded objects zip | `map-embedded-objects.md` |
| `0x0304305B` lightmap | `map-lightmap.md` |
| `0x0305B00F` validation ghost | `map-validation-ghost.md` |
| `0x03043049` MediaTracker | `map-mediatracker.md` |

Readers: `tools/tmmaps/src/map.rs` (the surgery reader, byte-offset based),
`tools/tmmaps/src/header.rs`, `tools/mapgeom` (placement). Confidence **[FILE]**
unless marked.

## 1. Header (user data)

| chunk | content | parsed by |
|---|---|---|
| `0x03043002` | TM2020 version **13**: `u8 version`, `u8 needUnlock` (the password flag the MENU checks before the body loads), then the times as `u32` ms at byte offsets **+5 bronze, +9 silver, +13 gold, +17 author, +37 authorscore** (`tmmaps validate` writes them; 2026-09-11), cost, multilap, type, … | `map.rs::remove_password`, `tmmaps validate` |
| `0x03043003` | "Common": lookback version, `Ident mapInfo` (uid, collection, author), `string mapName`, `u8 kind`, … — the uid and name here are the ones the game keys caches by | `map.rs::set_map_name`, `set_map_uid` |
| `0x03043004` | version word | opaque |
| `0x03043005` | ONE GBX string: the community XML (§1.1) | `header.rs::header_xml` |
| `0x03043007` | thumbnail: `u32 version`, `u32 thumbSize`, `<Thumbnail.jpg>` JPEG bytes `</Thumbnail.jpg>`, `<Comments>…</Comments>` | size only |
| `0x03043008` | author info | opaque |

### 1.1 The XML chunk

```xml
<header type="map" exever="3.3.0" exebuild="2023-07-10_19_57" title="TMStadium" lightmap="8">
  <ident uid="Z4p7Gy3gjXINzu8pgm_WzYYjtmg" name="$o$i$aa0Kack…" author="…" authorzone="…"/>
  <desc envir="Stadium" mood="Day" type="Race" maptype="TrackMania\TM_Race" mapstyle=""
        validated="1" nblaps="0" displaycost="…" mod="" hasghostblocks="1" nblocks="…"/>
  <playermodel id=""/>
  <times bronze="…" silver="…" gold="…" authortime="…" authorscore="…"/>
  <deps><dep file="Skins\…"/></deps>
</header>
```

Facts, each measured (`tools/tmmaps/src/header.rs`, `tools/gbx/src/name.rs`):

* The map's declared NAME is on `<ident>`, not `<desc>`; a read that said `desc`
  printed `name -` for every map for weeks and let a title invented from skin
  dependencies ("The Magnet Trial") be published for a map whose header says
  `[object Object]` (2026-08-25 name audit).
* Names carry two encodings: XML escapes (`Miru&apos;s Hell 2`,
  `Pain ft Mango &amp; Teuflum`) and ManiaPlanet markup
  (`$o$i$aa0Kack$05ay Re$09alo$6a0ad$aa0ed $4f0#290` = "Kacky Reloaded #290").
  Unescape, then strip, in that order.
* `authortime` is in milliseconds; it is a yardstick the FILE carries.
* `lightmap="N"` is the baked-lighting version the CLIENT must load; the
  dedicated server never reads it. `hasghostblocks="1"` = drive-through blocks.
* `validated="1"` ⇔ the body carries a real validation ghost in `0x0305B00F`;
  writers that strip the ghost set it to `0`.
* `<playermodel id="%s"/>` is the exe's format string: the header carries only
  the vehicle id (`CarSport`, `CarSnow`, `CarRally`…), never the full ident
  (memory `gbx-map-surgery-lookback-tables.md`).
* `mood="Day"` is not the whole story: Summer 09 is set at NIGHT although its
  header says `Day` — the day time lives in the body (`dayTime` word, seen as
  `0xDAAB` on map 12); a `Night64` decoration exists for Stadium
  (`48x48Screen155Night`) and not for GreenCoast.
* The header is PLAINTEXT, so a corpus can be bucketed by `exebuild`, uid, name
  with no decompression at all (memory `tm2020-dedicated-server-validatepath.md`).

### 1.2 The map uid

27 characters `[A-Za-z0-9_-]`, generated by the editor and **changed on every
save**. Where it lives: header `0x03043003` (`Ident.id`), header XML
`<ident uid=…>`, body `0x0304301F` (the first Ident of the body), and in every
pure ghost that binds to the map (`ghost-cgamectnghost.md` §5). Rules learned:

* The dedicated server does **not** check the uid against the content; every
  segment map keeps the original uid so unmodified ghosts resolve against it —
  but two maps with one uid must never share a `UserData/Maps` directory (the
  server binds the uid to whichever it found first) (`tools/tmmaps/src/oracle.rs`).
* The game unlocks its OWN maps by uid: change the uid of a password-protected
  campaign map and the editor asks for the password (`remove_password()` first).
* A map's embedded validation ghost holds the uid AS OF THE VALIDATION SAVE, not
  necessarily the file's (memory `tm2020-embedded-author-ghost.md`).
* `tmmaps tiny` writes `Tiny` + the first 23 bytes of the source uid — distinct,
  still 27 bytes, so every literal copy is rewritten length-preserving
  (`tools/tmmaps/src/tiny.rs`).
* A game-written cache file is keyed by the map's NAME, not its uid
  (`MediaTrackerCache\MTAuthorGhost<name>.Ghost.gbx`,
  `LaunchedCheckpointsCache\<name>.LaunchedCP.gbx`, the Autosaves replay) —
  `ghost-caches.md`.

## 2. Body chunk catalogue

The blocks chunk `0x0304301F` and the MediaTracker `0x03043049` are
NON-skippable; almost everything else is skippable (`tmmaps chunks MAP` lists
the skippable ones with sizes). Chunks we read or write:

| chunk | skippable | content | our handling |
|---|---|---|---|
| `0x0304301F` | no | Ident mapInfo, string name, Ident decoration, `Int3 size`, `u32 needUnlock`, `u32 version`, `u32 nbBlocks`, block records… | `map-blocks.md` |
| `0x03043029` | yes, 20 B | `[u8;16]` password hash + `u32` CRC32 | deleted by `remove_password` |
| `0x03043036` | yes | the thumbnail camera (position, pitch/yaw/roll, fov …) — what a MediaTracker render falls back to when no clip triggers (`tools/tinyctl/src/mtrender.rs`) | read only |
| `0x03043040` | yes | items: `u32 version (8)`, `u32 u01`, `u32 sizeOfNode` (TWO sizes that must agree), `u32 archiveVersion`, `u32 nb`, records, snapped-on tables | `map-items.md` |
| `0x03043043` | yes | zone genealogy: `u32 version`, `u32 innerLen`, `u32 count`, records | `map-genealogy.md` |
| `0x03043048` | yes | baked blocks: `u32 version`, `u32 u01`, `u32 nb`, records, `u32 u02`, `u32 nbBakedClips` (must be 0 for our reader) | `map-blocks.md` |
| `0x03043049` | **no** | MediaTracker: version 2, five clip/group node refs, `Int3 triggerSize` | `map-mediatracker.md` |
| `0x03043051` | yes | title id + build version — shares the BODY lookback table (memory `gbx-map-surgery-lookback-tables.md`) | copied verbatim |
| `0x03043054` | yes | embedded objects: manifest + ZIP | `map-embedded-objects.md` |
| `0x0304305B` | yes | lightmap: `u32 version`, `u32 hasLightmaps`, `u32 u01`, `u32 u02`, frames… | `map-lightmap.md` |
| `0x0304305D` | yes | an octree: `version 1`, tree count 0/1, `u32 grid` (power of two: 32/64/128), `Int3`, `u32 n`, nodes (internal: `i32 parent` + 8 child indices; leaf: `i32 parent` + `u8` flag 1/3/7). Names no block or item, so block deletion leaves it valid. GBX.NET lists it as "ignore" | `map.rs::octree_chunk_summary` (2026-09-07) |
| `0x0304305F` | yes | free-block positions: `u32 version`, then **24 B per free block**: `Vec3 position`, `Vec3 pitch,yaw,roll` — unbaked free blocks first, then baked free blocks, in record order; the walk must land exactly on the chunk end | `map-blocks.md` §3 |
| `0x03043062` | yes | `u32 version`, one **colour byte** per unbaked block, then per baked block, then per item | `map-items.md` §4 |
| `0x03043063` | yes | `u32 version`, one **AnimPhaseOffset byte** per item (eighths of the period) | `map-items.md` §4 |
| `0x03043068` | yes | `u32 version`, one **lightmap-quality byte** per block, baked block, item | `map-items.md` §4 |
| `0x03043069` | yes | `u32 version`, one macroblock-instance index (`i32`) per authored block, then per item, then `Int2[]` instance (id, flags) pairs | `map-items.md` §4 |
| `0x0305B00E` | yes | precedes the ghost chunk; a `Dummy` ghost is inserted right after it when the map has no `0x0305B00F` | position marker |
| `0x0305B00F` | yes | validation ghost: `u32 version (0)`, `u32 byteLength`, CGameCtnGhost node written with class id and no index (null = `FFFFFFFF`) | `map-validation-ghost.md` |

**The `0x0304305F` size-word trap.** Inside a REPLAY's carried map this chunk
declares a size that runs past the end of the carried map. A chunk walk over
the replay body that "corrects" that size word writes four bytes into the
middle of the map: every string still reads back and the replay validates to
nothing (7.241 → DNF) (`tools/gbx/src/container.rs::replace_strings`). Our
readers protect the carried map's byte range from every fixup.

## 3. Coordinates

* Block cell size 32 × 8 × 32 m (`CELL_XZ`, `CELL_Y`). Cell `(cx,cy,cz)` →
  world `(32·cx + lx, 8·cy + yoff + y, 32·cz + lz)`, `lx/lz` the block-local
  point turned by `dir` (`map-blocks.md` §2).
* The file stores a grid block's x and z cell **one higher** than the world
  grid (`BlockRec::coords` subtracts `(1,0,1)`); items store the cell as is.
* `yoff` = world y of cell row 0 is the ENVIRONMENT's, not the file's:
  Stadium −64 (a cell-9 deck at y 10 = 9·8 − 64 + the prefabs' +2), BlueBay
  −40, GreenCoast −40, RedIsland −120, WhiteShore −120, each measured on a
  Summer 2026 map (`map.rs::ground_y`). It was −62 until 2026-09-07: the block
  TOP had been read as the cell floor, and every converted map floated 1 m.
  `mapgeom` FITS it per map instead (`tools/mapgeom/MAPGEOM.md` §4.2); the
  `CGameCtnDecorationSize` (`0x0303B000`) that almost certainly carries it has
  no reader yet.
* Axes: X east, Y up, Z north, metres — the same frame ghost samples use; no
  handedness flip anywhere in the tools.

## 4. What the game does with a map, measured

* The dedicated server refuses a map with an uncompressed (`'U'`) body
  (`Can't load map`) and one whose shared lookback table changed length
  (`Can't load map`); it does NOT check the uid, the header, the `lightmap`
  version or block model names (`tmmaps renamecheck`: a block renamed to a
  model no library has still validates the reference ghost at 19.538).
* The client narrates a refusal as `Updating data... $<$> (???)` with the
  progress bar at 0 — the map's own name renders as `(???)` when a block
  model cannot be resolved; four renamed checkpoint models did that
  (`MAPS.md` §6). A spliced or re-emitted map with stock names loads in ~10 s.
* Waypoint TAGS in the file are ignored by the game; what a waypoint does is
  decided by the block/item MODEL (`map-blocks.md` §5).
* A finish block triggers ~100–150 ms before a checkpoint block in the same
  cell (cell entry vs cell centre); `GateFinish32m`'s trigger is geometrically
  identical to `GateCheckpointLeft32m`'s (`tools/tmmaps/src/segments.rs`).
* The editor's re-save regenerates the parked blocks' neighbours (8581 Lake
  blocks for a 5737-block map) and DROPS every item whose collision mesh is
  empty (`tools/shootctl/src/lightmap.rs`, 2026-09-07).
* `PluginMapType.SaveMap(path)` renames the map to the file's stem
  (`shootctl lightmap`).

## 5. Not known / not read

* Header `0x03043002` beyond byte 1, `0x03043004`, `0x03043008`.
* `0x03043036` beyond "it exists and is the render fallback camera".
* Most body chunks between `0x03043022` and `0x0304305A`: copied verbatim,
  never decoded (§6 lists what one real map carries).
* `0x03043048`'s trailing baked-clip entries (`nbBakedClips > 0`): refused,
  never seen on 285 maps.
