# Handover — the long-haul harness, 2026-08-24

*What was built, what it does not cover, and what would break it.*

---

## What is running

A supervisor process on the box, a cron heartbeat that outlives every session,
and a real workload. State lives in this repo and is pushed to GitHub
continuously; a copy of the state tree also goes off the box every bank, so a
fresh box needs nothing but a public clone and an x509 cert.

| | |
|---|---|
| harness | `tools/haul` → `tmhaul`. No third-party dependencies: it is the first thing a fresh box builds, and every dependency is one more way for that to fail |
| worker | `tools/resim` → `tmresim`, the standing re-simulation sweep |
| state | `autopilot/state/`, append-only, sharded per box |
| operator's manual | `autopilot/HARNESS.md` |
| status for a human | `autopilot/STATUS.md`, regenerated, never hand-typed |
| failures already paid for | `autopilot/OPS-LOG.md` |
| tests | 87 in `haul`, 12 in `resim`, all green |

---

## What it does NOT cover

**It does not search.** The harness supervises a worker; today that worker is
the re-simulation sweep. **The explorer is deliberately NOT integrated** — the
lead held it back on 2026-08-24: its run begins at the wrong position or its
state locator tracks the wrong object, and its five `confirmed` tapes omit the
replay frame needed to reproduce them. Automating a broken worker is worse
than not automating one. What went in instead is the general acceptance gates
(`tmhaul claim`), which refuse exactly that shape of claim from ANY worker.

So nothing here has yet supervised a real search, and the first time it does,
something will be wrong that this could not have found.

**It cannot provision a box by itself.** Banking, verifying, standing down and
retiring are all automatic; *acquiring the replacement machine* is a platform
action that only an agent session can take. The cron heartbeat is what supplies
that agent every thirty minutes. If the orchestrator is down for longer than a
box's remaining lease, the run stops cleanly and waits — it does not lose work,
but it does not continue either.

**The map corpus is refetched, not carried.** Ruled 2026-08-24: Nadeo's map
files do not go in a public repo. `autopilot/config/maps.rec` carries what is
needed to get each one back — uid, name, author time from the map's own
header, the documented GET route, an md5 and a byte count, the start line, the
checkpoint count — and `tmresim maps verify` proves a refetch came back
identical. 94 map files registered, 94 verified. **What is untested is the
refetch itself**: every map is already on this box, so nothing here has yet
proven that a row's URL returns the bytes its hash names. That is the next
thing I would check, and it needs a box with no corpus on it.

**The start-position check is telemetry-derived.** It reads the container's
own `CPlugEntRecordData`, and a synthesised tape carries its template's
telemetry — so for a tape our tooling wrote, the position it reports may be
the template's rather than the run's. The authoritative answer is a live
re-simulation reading tick 0, which the explorer can report through the worker
contract. Every line the sweep prints says telemetry-derived for this reason.

**No alarm pages a human.** Firing is recorded, surfaced on the status page,
and handed to the woken session as a DO NOW list. Nothing sends a message,
because nothing is allowed to.

**The budget's switch condition is measured, not executed.** When 8,000,000
evals or ten productive hours are reached, the harness says so on the status
page and in every heartbeat. Adding the learned ordering over archive bins is
somebody's judgement, not an automatic action.

## What would break it

Roughly in order of how likely I think each is.

1. **The render box.** It is the only machine that can push to GitHub, it is
   shared, it is Windows, and it drives the game for other work. If it is down
   or its deploy key is rotated, pushes stop. Mirroring to a paste keeps
   working (different credential, different service), so no work is lost — but
   the repo, which is the state of record a human reads, goes stale, and
   `unbanked_drift` is the only thing that will say so.
2. **The navi credential expiring.** `~/.navi/credentials.json` was minted in
   May. When it stops working the bridge dies and `push = auto` silently
   resolves to `none`. It is not silent about the *consequence* — the alarm
   fires — but the cause will look like something else.
3. **A worker that lies about progress.** The supervisor believes the eval
   counter. A worker that increments it without doing anything would look
   perfectly healthy. Nothing here can detect that; only the plain oracle
   re-simulating the written tape can, which is why that rule is standing.
4. **Two supervisors on two boxes at once.** The logs merge cleanly by
   construction, and queue claims are leases, so this is survivable — but both
   would push to `main` and one would have to rebase. Untested. Do not run two
   deliberately.
5. **A `job.rec` edit that does not parse.** The config refuses to half-parse,
   so the supervisor will not start rather than run with a threshold nobody
   set. That is the right failure, but on a fresh box, at 3am, it looks like
   the harness is broken.
6. **Clock skew between boxes.** Every record is stamped by its writer. A box
   with a wrong clock would reorder the merged journal and could make a stall
   look like a gap. Not defended against.

## What I would want next, in order

1. **Fix the explorer, THEN put it under the harness** — in that order, and
   `tmhaul claim` is the acceptance test it has to pass. Set
   `worker_drives = yes` in the same change. Everything above is instrument
   work, and instrument work that never produces a driving car is worth
   nothing.
2. **Prove a map refetch end to end** on a box with no corpus — the registry
   says it should work and nothing has demonstrated it.
3. **A second push route** that does not go through one shared Windows machine.
