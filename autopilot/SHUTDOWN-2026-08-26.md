## Durable final state

The final live sample before shutdown was eval **42,036**. `tmhaul stop` wrote a
`run_stop`, banked, verified every manifest entry, retired the active box, and
pushed commit `d380f27c1e06` to GitHub when WhiteStick briefly came back.

The configuration's `worker_cmd` is now intentionally empty. This is a second
fail-closed guard after removing the scheduler: even a stale copied
`tmhaul watch` command refuses to start. There is no autonomous wakeup or
machine restart hook left.

Published periodic/heartbeat commits were **not rewritten or deleted**. They
are history, and rewriting public Git history would be worse cleanup than
leaving an audit trail. This cleanup is a normal forward commit.

## To restart someday

Restarting is a new decision, not recovery from an alarm. It requires all of:

1. choose a worker and restore `worker_cmd` in `autopilot/config/job.rec`;
2. start a supervisor explicitly;
3. if unattended operation is desired, create a new scheduler explicitly;
4. if GitHub push through WhiteStick is desired, restore a credential-delivery
   service explicitly.

Do not treat the absence of samples, a stopped run, or an empty worker command
as a fault: they are the requested state recorded here.
